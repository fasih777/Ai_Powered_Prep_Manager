Product Requirements Document (PRD)

AI-Powered Prep Manager

Version: 1.0 | Status: Draft | Owner: Project Planning

1. Problem Statement

Products prepared for inbound shipment must meet packaging and labelling requirements (polybagging, warning labels, FNSKU placement, barcode coverage, expiry visibility, handling marks). Prep errors are often invisible until weeks later, when they surface as compliance issues and fees. A work order proves intent, not execution — there is no reliable way today to confirm a unit was actually prepared correctly at the time of processing.

2. Goal

Build an AI agent that reviews photographs of a prepared unit against authoritative prep requirements and returns a per-check verdict (Pass/Fail/Uncertain) with evidence and an overall PREP STATUS, catching errors before the unit ships instead of weeks later.

3. Users & Use Cases

User Use Case
Prep station operator Takes photos post-prep, gets instant pass/fail feedback before moving the unit on
QA / compliance reviewer Audits a sample of prepped units, reviews AI-flagged failures and uncertain cases
Ops manager Monitors prep-quality trends, error types, and re-work rates

4. Scope

In Scope — Visual Checks

  1. Polybag presence
  2. Polybag sealing
  3. Suffocation warning presence
  4. Warning visibility & legibility
  5. FNSKU label placement
  6. FNSKU placed on an appropriate surface (not on a seam/curved edge/opening)
  7. Original manufacturer barcode covered
  8. Expiry-date visibility
  9. Required handling marks (fragile, liquid, this-side-up, etc., where applicable to category)
  10. Other category-specific visual prep requirements defined in the reference rule set

Explicitly Out of Scope

  • Any requirement not visually verifiable (e.g., poly bag material thickness/mil rating, adhesive strength, weight/dimension accuracy) — the agent must declare these Uncertain / Not Verifiable, never guess.
  • Physical remediation/re-prep workflow (routing a failed unit) — v1 only reports status; workflow integration is a future phase.
  • Non-prep quality issues (product damage, wrong item) unless they coincide with a listed check.

5. Inputs

  • Product photograph(s) — multiple angles where available
  • Packaging photograph(s)
  • Product/category metadata (category drives which checks/marks apply)
  • Label & barcode crops/zoom images (if separately supplied)
  • Prep requirements reference (authoritative rule source — see §7)
  • Sample preparation instructions / work order (context only, not proof of execution)

6. Output Format

For each applicable check:

<Check Name>: PASS | FAIL | UNCERTAIN
Reason: <short explanation when FAIL/UNCERTAIN>
Evidence: <what in the image supports this — region/label text/observation>

Then:

PREP STATUS: PASS | FAIL | UNCERTAIN

Rules for overall status:

  • FAIL if any single applicable check is FAIL.
  • UNCERTAIN if no check FAILs but one or more required checks could not be conclusively verified from the provided evidence.
  • PASS only if every applicable check is PASS.

7. Reference Requirements (Authoritative Rule Source)

The agent must never invent compliance rules. All pass/fail logic is grounded in a versioned, structured rule set (see TRD §4) derived from the authoritative prep requirements provided for the challenge (e.g., FBA-style prep & labelling requirements), parameterized by product category. The rule set — not the underlying vision/language model — is the source of truth for what to check and what counts as compliant; the model's role is visual perception and evidence extraction against that rule set.

8. Functional Requirements

ID Requirement
FR1 Accept one or more images + category metadata as a single "prep review" request
FR2 Determine, from category metadata + rule set, which checks are applicable to this unit
FR3 For each applicable check, output PASS/FAIL/UNCERTAIN with a human-readable reason and cited visual evidence
FR4 Perform OCR on labels to verify presence/legibility of suffocation warning text and expiry date
FR5 Perform spatial/geometric reasoning to judge FNSKU placement (flat surface vs. seam/curved edge/opening)
FR6 Detect and cross-check the original manufacturer barcode region for coverage
FR7 Flag a check as UNCERTAIN (never silently pass or fail) when image evidence is insufficient — e.g., poor lighting, occlusion, missing angle, non-visual property
FR8 Aggregate individual checks into one overall PREP STATUS using the rule in §6
FR9 Log every decision with the evidence used, for audit/appeal
FR10 Support human override/correction of any verdict, captured for future calibration

9. Non-Functional Requirements

  • Reliability over confidence: false PASS is materially worse than false FAIL or UNCERTAIN; the system should be tuned conservatively.
  • Explainability: every verdict must be traceable to a specific rule ID and a specific piece of visual evidence.
  • Latency: near-real-time feedback at the prep station (target: single-digit seconds per unit).
  • Auditability: full decision trail retained for post-hoc compliance review.
  • Extensibility: new categories/checks addable via rule-set updates, without retraining or prompt-rewriting the core agent.

10. Success Metrics

  • Reduction in downstream compliance fees/issues tied to prep errors
  • Precision/recall on each check type against human-reviewed ground truth (esp. false-PASS rate ≈ 0)
  • % of reviews resolved as PASS/FAIL vs. UNCERTAIN (UNCERTAIN rate should reflect genuine evidence gaps, not model laziness)
  • Operator time from photo capture to verdict

11. Test Scenarios (Acceptance Criteria)

  1. Correctly sealed polybag → PASS across all checks
  2. Missing warning → FAIL, Suffocation Warning
  3. Obscured warning → FAIL or UNCERTAIN depending on legibility, with reason
  4. Incorrect FNSKU placement → FAIL, FNSKU, with placement reason
  5. FNSKU on a seam → FAIL, FNSKU, "placed across seam/curved edge"
  6. Original barcode visible/uncovered → FAIL, Original Barcode
  7. Covered expiry date → FAIL or UNCERTAIN, Expiry Date, "not visible"
  8. Missing handling mark → FAIL, Handling Marks
  9. Fully correct preparation → overall PASS
  10. Visually ambiguous preparation (e.g., angle doesn't show a required surface) → UNCERTAIN, not a guessed PASS/FAIL

12. Risks & Mitigations

Risk Mitigation
Model hallucinates a rule not in the reference set Hard-constrain checks to the structured rule set; model may only select/apply, not author, rules
Overconfident verdict on poor-quality photo Require minimum evidence quality heuristics; default to UNCERTAIN below threshold
Category misclassification changes which checks apply Validate/display category used for the review; allow operator correction
OCR misses low-contrast or small print Multi-pass OCR + flag low-confidence text as UNCERTAIN rather than PASS
