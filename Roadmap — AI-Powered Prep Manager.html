Roadmap — AI-Powered Prep Manager

Derived from: PRD v1.0, TRD v1.0

Guiding Principle

Ship in order of risk reduction: prove the rule-engine-over-perception architecture and the UNCERTAIN-vs-guess behavior early (highest project risk), then widen check coverage, then integrate into the real workflow, then scale/optimize.

Phase 0 — Foundations (Rule Set & Data)

Goal: Nothing else can start until the authoritative rules exist in structured form and test data exists.

Workstream Deliverable
Rule authoring Versioned rule set (JSON/YAML) for a first category, covering all 10 check types, each tagged visually_verifiable: true/false
Test data Labeled image set covering all 10 PRD test scenarios + category variants, with human ground-truth verdicts
Schema PrepReview / check / evidence data model finalized (TRD §3)

Exit criteria: Rule set v0.1 reviewed by compliance owner; ≥50 labeled test images across pass/fail/uncertain cases.

Phase 1 — MVP: Core Pipeline, Narrow Scope

Goal: End-to-end pipeline working for one category and a subset of checks — validate the architecture, not full coverage.

Workstream Deliverable
Perception Object/segment detector + OCR module wired as callable tools
Rule engine Deterministic evaluator consuming rule set + evidence → verdict
Aggregator Overall PREP STATUS logic (FAIL > UNCERTAIN > PASS)
Checks in scope Polybag presence, Polybag sealing, Suffocation warning presence, Original barcode covered
API POST /v1/prep-review returning structured JSON (TRD §7)
Reporting Human-readable report matching challenge example format

Exit criteria: All Phase-0 test images for these 4 checks correctly classified, with zero false PASS; UNCERTAIN correctly triggered on the ambiguous test case.

Phase 2 — Full Check Coverage

Goal: Extend perception + rules to every check in the PRD.

Workstream Deliverable
Spatial/geometry module Surface classification for FNSKU placement (flat vs. seam/curved edge/opening)
Barcode/label reader FNSKU decode + manufacturer barcode detection/coverage check
OCR extension Expiry-date extraction, warning legibility scoring, handling-mark text/icon recognition
Rule set expansion All 10 check types, multi-category support
Confidence calibration Per-check thresholds tuned so UNCERTAIN reflects genuine evidence gaps

Exit criteria: Full 10/10 PRD test scenarios pass acceptance criteria across ≥2 product categories.

Phase 3 — Reliability, Audit & Human-in-the-Loop

Goal: Make the system trustworthy enough to act on, not just accurate in a lab.

Workstream Deliverable
Audit trail Immutable logging of evidence + rule_id + rule_set_version per review
Override workflow Reviewer override endpoint + correction capture for future calibration
Image quality gate Pre-check on blur/exposure/resolution; forces UNCERTAIN below threshold
Operator UX Minimal capture-guidance flow (angles/lighting) to reduce avoidable UNCERTAINs
Non-visual requirement handling Explicit "NOT VERIFIABLE FROM IMAGE" path fully wired and tested

Exit criteria: False-PASS rate ≈ 0 on held-out set; every verdict traceable end-to-end in an audit review.

Phase 4 — Scale, Observability & Extensibility

Goal: Operate in production across the full category catalog with monitoring and easy rule updates.

Workstream Deliverable
Observability Dashboards: verdict distribution, UNCERTAIN rate, confidence drift
Rule-set ops Hot-reload rule updates without redeploying perception layer
Category rollout Rule sets + evidence extractors validated across all target categories
Performance p95 latency < 8s/unit at target throughput
Regression suite Automated re-run on every rule-set or model version bump

Exit criteria: Production SLAs met; new category or rule change shippable without a code deploy.

Cross-Phase Risks to Track

  • False PASS is the single most dangerous failure mode — gate every phase exit on this before moving forward.
  • Rule-set ownership/update process (from PRD Open Questions) must be settled by end of Phase 0 — it blocks Phase 2/4.
  • Decision on where human review sits in the flow (pre-ship gate vs. sampling) should be made before Phase 3 UX work begins.
